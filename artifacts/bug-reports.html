[API][Following] Approved user is returned as unverified

High Reproducible

Environment

QA · Mobile build 1.x · API version 1

Precondition

A newly registered user has completed approval and the account status is visible as Approved.

Steps to reproduce

  1. Sign in using the approved test account.
  2. Request the Following feed.
  3. Inspect the user-verification field in the response.

Actual result

The service returns is_verified: false although the user is approved.

Expected result

The service returns is_verified: true, consistent with the approved account state.

Impact

Downstream features may treat an approved user as ineligible, causing incorrect access, feed, or onboarding behaviour.

Evidence attached

01 · Sanitized API response
Timestamp and correlation ID included
02 · Account state evidence
Approval state visible
03 · Relevant log window
No personal data included

[Data][Onboarding] Selected business area is not persisted

High Reproducible

Environment

QA · Android build 1.x · Test account with no prior onboarding data

Steps to reproduce

  1. Register and approve a new test user.
  2. Complete the onboarding steps.
  3. Select one or more business areas and continue.
  4. Reload the profile and verify the stored onboarding data through an approved validation method.

Actual result

The selection appears successful in the UI, but the stored relationship is missing. The information is lost after reload.

Expected result

Every confirmed selection is persisted once and returned consistently to the profile and dependent features.

Impact

Personalization and eligibility decisions can be wrong even though onboarding appears complete to the user.

Evidence attached

01 · Screen recording
Selection through reload
02 · Sanitized data check
No schema or real IDs exposed
03 · API/log comparison
Request accepted but relation absent
